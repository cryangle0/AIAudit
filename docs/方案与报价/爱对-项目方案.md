## 第一章 业务背景与项目价值

### 1.1 业务现状

童装电商业务覆盖国内外 11 个平台店铺：

**国内（7 个）**：抖音、淘宝/天猫、拼多多、快手、视频号小店、微信小店、小红书

**海外（4 个）**：俄罗斯 OZON、俄罗斯 Wildberries、英国 TikTok Shop、美国 Amazon

每月财务团队需要将 **平台账单**、**聚水潭 ERP 销售数据**、**自维护商品成本** 三方数据交叉核对，定位差异，并核算各店铺/各商品的真实利润。海外业务还涉及 **卢布、英镑、美元** 三种外币，需要按月汇率换算到人民币统一核算。

### 1.2 当前痛点

**痛点一：人工对账效率低**
每个平台账单字段格式不一致，财务需要打开多个 Excel 手工比对订单号、销售收入、聚水潭实发金额、聚水潭实发成本。一个店铺的月度对账要 3-5 天，11 个店铺累计要近一个月。

**痛点二：差异定位难**
订单可能出现"金额翻倍登记""聚水潭缺失""平台缺失""利润异常"等多种情况。没有统一规则，靠人工很难批量识别，常常漏掉问题单。

**痛点三：成本数据散落**
商品成本（标费/辅料/商品成本）放在各部门 Excel 里，调整后无法保证历史报表稳定，也没有审计追溯，财务和老板对不上数。

**痛点四：海外多币种换算**
俄罗斯卢布、英国英镑、美国美元，目前完全靠人工查汇率、按月换算到人民币，效率低且易错。

**痛点五：分配规则不透明**
推广费、运费险、红包、补贴等公共费用，目前靠经验估算分摊到具体订单/商品，老板看不清楚每个 SKU 的真实利润。

### 1.3 项目价值

| 价值维度 | 现状 | 上线后 |
|---|---|---|
| 月度对账时间 | 3-5 天 / 店铺 | 30 秒 / 店铺 |
| 差异识别准确率 | 70%（人工） | 95%+ |
| 海外汇率换算 | 人工查询 | 自动按月换算 |
| 成本变更追溯 | 无 | 操作人/时间/前后值全程可查 |
| 利润分析维度 | 仅店铺 | 商品/店铺/平台/品类 4 维度 |
| 报表口径统一 | 各部门各报各的 | 与既有 Excel 模板表头逐字一致 |

### 1.4 建设目标

按客户《财务自动对账系统-需求表》20 项需求 + 《系统初稿模板5.22》4 张核心报表的全部要求落地。系统覆盖 **商品资料维护、跨平台账单导入、聚水潭对账、汇率换算、费用归集与分配、利润核算、报表生成** 全链路。

## 第二章 功能模块概览

系统按业务核算闭环组织为 **6 大模块、19 个功能页**：

### 2.1 商品管理（3 个功能）

| 功能 | 解决的问题 |
|---|---|
| 商品资料 | 集中维护款式编码/商品编码/商品名称/品类等基础信息，支持 Excel 批量导入 |
| 商品成本 | 按月维护「商品成本 + 标费 + 辅料」，对账时自动联动；支持随时调整 |
| 成本修改记录 | 谁在什么时候改了什么成本，前后值全部可查，便于审计追溯 |

### 2.2 利润核算中心（4 个功能）

| 功能 | 解决的问题 |
|---|---|
| 数据归集 | 推广费/运费险/红包等公共费用按类型集中录入 |
| 分配标准 | 自定义分配规则（按收入比例/按件数/按订单数/平均/直挂订单），透明可配置 |
| 数据分配 | 公共费用按规则自动分摊到每个订单/商品，每分钱都有出处 |
| 利润分析表 | 商品/店铺/平台/品类 4 个维度切换，看清各维度真实盈利能力 |

### 2.3 数据中心（7 张报表）

| 报表 | 业务用途 |
|---|---|
| 应收汇总表 | 店铺/商品维度：期初/应收/核销/期末（数量+金额） |
| 应收明细表 | 订单级追踪应收余额 |
| **账单汇总表** | 店铺月度账单收支汇总（与客户 Excel 模板表头一致） |
| **账单明细表** | 订单级收支明细 |
| **店铺利润表** | 销售收入/退货/销售成本/平台服务费/佣金/推广费/毛利/毛利率/退货率/确收率 |
| **差异分析表** | 对账主入口：上传账单 → 一键对账 → 自动定位差异 |
| **商品利润表** | 商品级利润排行 + 月度趋势柱状图 |

加粗的 4 张为客户《系统初稿模板5.22》对应的核心报表。

### 2.4 汇率管理（1 个功能）

按客户既定规则：**账单期间 → 取次月 1 日汇率**（如 1 月账单取 2 月 1 日汇率）。支持人民币 / 美元 / 卢布 / 英镑 4 种币种，按月维护。海外平台收入自动换算为人民币展示。

### 2.5 店铺管理（1 个功能）

集中维护店铺名称、所属平台、默认结算币种、营业状态、结算规则，与对账流程联动。

### 2.6 系统设置（3 个功能）

角色管理（财务主管/财务/运营/只读等 5 种角色）、权限矩阵、数据备份（一键导出全部数据归档）。

## 第三章 核心业务场景

### 3.1 月度对账主流程

财务进入【差异分析表】，选择平台和月份，上传两个文件：
1. 平台资金账单 Excel（如抖音资金账单）
2. 聚水潭导出 Excel

点击【开始对账】，系统在 30 秒内完成：
- 自动按订单号匹配两边数据
- 把订单分到 5 个差异桶（一致 / 金额翻倍 / 聚水潭缺失 / 平台缺失 / 利润异常）
- 生成 KPI 卡片（总订单 / 营收 / 成本 / 真实利润 / 差异数）
- 列出所有差异订单，可点击下钻查看原始流水
- AI 给出一句话差异原因提示

**5 类差异桶定义**：

| 差异类型 | 触发条件 | 业务含义 |
|---|---|---|
| 一致 | 平台销售收入 ≈ 聚水潭金额 | 完全对齐，无需处理 |
| 金额翻倍 | 聚水潭多行登记，金额累计为平台 N 倍 | 售后/换货行重复登记 |
| 聚水潭缺失 | 平台有这单，聚水潭没有 | 未发货 / 导出条件遗漏 |
| 平台缺失 | 聚水潭有这单，平台账单没有 | 未结算 / 跨月在途 |
| 利润异常 | 真实利润 偏离 系统毛利 较大 | 成本错登 / 退款漏冲 |

### 3.2 商品成本变更与版本控制

财务在【商品成本】页编辑某个 SKU 的标费/辅料，系统自动：
- 写入【成本修改记录】（操作人 / 时间 / 字段 / 修改前 / 修改后）
- **后续对账使用新成本，已生成的历史报表保持锁定不变**

这样保证了财务和老板对历史数据的稳定信任，也保证了变更可追溯。

### 3.3 海外平台多币种对账

第一次使用 OZON 等海外平台时：
1. 在【汇率维护】录入次月 1 日的卢布/美元/英镑汇率
2. 在【店铺/平台配置】给海外店铺标记币种
3. 上传海外平台账单
4. 系统按"账单期间次月 1 日"汇率自动换算为人民币入账
5. 报表统一用人民币展示

如果次月 1 日是节假日，自动取前一个工作日的汇率。

### 3.4 公共费用三层分配

每月把"推广费 12,500 元 / 运费险 2,800 元 / 红包 4,200 元"等公共支出录入【数据归集】。

系统按【分配标准】自动分摊：
- 推广费 → 按销售收入比例分摊到每个订单商品
- 运费险 → 按订单数平均分摊
- 平台服务费 → 直接挂到对应订单（如果账单已带订单号）
- 其他费用 → 按设定的优先级匹配规则

分摊后在【数据分配】页可以查看每分钱的去向（按组织 / 店铺 / 商品 / 订单 4 个维度）。【商品利润表】和【利润分析表】会自动包含这些分摊费用，老板看到的每个 SKU 利润都是真实利润。

## 第四章 实施计划与里程碑

### 4.1 总体周期

**20 个工作日 / 4 周自然时间**，分 4 个阶段交付。

| 阶段 | 工作日 | 自然周 | 主要产出 |
|---|---|---|---|
| 第一阶段 | 4 天 | 第 1 周 | 需求确认 + 商品管理（资料/成本/审计） |
| 第二阶段 | 6 天 | 第 2 周 | 对账主流程 + 7 个国内平台 + 聚水潭对接 |
| 第三阶段 | 6 天 | 第 3 周 | 7 张报表 + 汇率自动换算 + 公共费用分配 |
| 第四阶段 | 4 天 | 第 4 周 | 4 个海外平台 + 系统设置 + 测试上线 + 培训 |

### 4.2 关键里程碑

**M1（第 1 周末）**：需求确认书签字，原型评审通过

**M2（第 2 周末）**：抖音 + 聚水潭对账主流程跑通，能完成首次对账演示

**M3（第 3 周末）**：7 张报表全部上线，海外多币种对账可演示

**M4（第 4 周末）**：全功能交付，正式上线，财务团队培训完成

### 4.3 风险与应对

| 风险点 | 应对措施 |
|---|---|
| 客户账单格式与样例不一致 | 第 1 周收集 3-5 个真实账单样本，提前调试 |
| 海外平台账单字段未知 | 客户提供 1 份样本即可，否则用通用模板 |
| 对账规则边界情况 | 第 3 周末用 1 个月真实数据回归测试 |

## 第五章 交付内容与验收标准

### 5.1 交付清单

| 类别 | 内容 |
|---|---|
| 系统 | 完整可访问的线上系统（按客户指定地址上线） |
| 文档 | 用户操作手册（财务版） |
| 数据 | 11 个平台演示数据 + 全模块种子数据，开箱即可演示 |
| 培训 | 1 次现场或远程培训 + 培训录屏 |
| 模板 | 商品资料导入模板、商品成本导入模板、费用归集导入模板 |

### 5.2 验收标准

**功能验收**
- 19 个功能页全部可正常使用
- 7 张报表表头与客户《系统初稿模板5.22》逐字一致
- 客户《财务自动对账系统-需求表》20 项需求全部满足

**对账准确性**（用客户真实抖音账单做基准）
- 总订单数误差 ≤ 0.5%
- 差异分类与人工审核一致率 ≥ 95%

**性能要求**
- 5 万行账单解析时间 < 3 秒
- 切换菜单页响应 < 0.2 秒

**多币种验收**
- 上传海外卢布账单，能正确按月汇率换算为人民币
- 跨币种在店铺利润表、商品利润表统一展示
